# Design proposal: a physics kernel, with institutions made of people doing things (contracts v0.2)

*Status: **approved (D28) and implemented (D29)**, on branch v0.2-contracts.*
- *Draft 1 (commit 12b79c9) let rules block and execute acts; superseded by D19.*
- *Draft 2 had money moved by "access" and automatic standing orders; superseded by D26 (banks).*
- *Built on decisions D18–D26 and [the borrowing survey](../research/borrowing-survey.md).*

---

## 1. Principles

1. **The kernel is physics.** Every human construct is expressed through it as data (D18).
2. **Laws have no power of their own. Entities act.** Breaking a law is possible wherever physics allows it (D19).
3. **Possession is physics; authority is not.** Organisations act through people and procedures (D20).
4. **The kernel never judges whether a record is valid** (D22).
5. **Institutions are world content.** An empty world is valid (D23).
6. **Proportional fidelity** (D25). A simplification may change *how much* or *how fast*, never *who acts* or *whether a safeguard works*.
   - Full fidelity: power, institutions, human levers, information.
   - Medium: the everyday economy.
   - Low: the financial system, construction details, geography.
7. **The loop is unchanged:** plain language → translator → blocks → sign-off → kernel.

**The test for every mechanism:** *in the real world, who actually does this, how, and at what cost?*

## 2. What the kernel knows

| | Contents | Does the kernel refuse on it? |
|---|---|---|
| **Physics** | **Time.** **Money**: conserved integer tokens, held in accounts; every account has a **custodian** (normally a bank), and only the custodian's people can physically move money out of it. **Land**: finite parcels. **Structures**: built by builders; physical capacity. **Bodies**: persons exist, are somewhere, can't be conjured. **The boundary** (the world's edge). *Later:* work capacity (§9). | **Yes. These are the kernel's only grounds for refusal.** |
| **Records** | Claims, agreements, statements (laws, procedures, norms, decisions, permits, judgments, ballots, instructions), each with an **author**, a time and a claimed **basis** | **No.** Stored and shown; never judged valid or invalid (D22). |
| **Perception** | What each seat can see: accounts, records, physical sites, messages | Configured per seat (§7) |

**Seats are people or roles in the world.** Each seat belongs to an entity (a person, a bank, the city), has perception channels, a controller (code by default, an LLM, eventually a human) and a framing. A seat belonging to a bank *can* physically move money in that bank's custody. That includes a rogue bank clerk, which is realistic.

## 3. Acts (blocks)

### 3.1 Physical acts: the kernel checks physics only

| Block | Performed by | Physics the kernel checks |
|---|---|---|
| `transfer` | A seat of the **source account's custodian** (a bank clerk or a bank's payment system) | Funds exist; no overflow; the boundary can't pay |
| `open_account` / `close_account` | A seat of the custodian | Closing requires a zero balance (money must go somewhere) |
| `construct` | A seat of the **builder** | Parcel exists and is empty; the builder can cover the catalogue's **materials cost**, which is paid to the boundary as part of building (*liberty: material purchases aren't modelled*). The structure completes after the build time. **No ownership is assigned**; who owns it is a record. |
| `demolish` | A seat of whoever does the demolishing | Structure exists; demolition cost as for construction. Whose building it is doesn't matter to physics. |
| `occupy` / `vacate` | The occupant, or (for removal) whoever physically removes them | Capacity; the occupant is present. Removing someone else is eviction: possible, lawful or not depending on the records. |

### 3.2 Record acts: the kernel stores, never judges

| Block | What it records |
|---|---|
| `create_entity` / `dissolve_entity` | Declares or winds up an organisation. Whether it's recognised is interpretation. |
| `record_claim` / `transfer_claim` / `release_claim` | A claim (§4.1), authored by whoever records it. A forged title is possible; the record shows who wrote it. |
| `propose_agreement` / `sign_agreement` / `give_notice` | An agreement (§4.2). Whether a notice is valid under the terms is interpretation. |
| `publish` / `withdraw` | A statement (§4.4), authored by a seat and naming the entity it claims to speak for |
| `vote` | A choice on a ballot. **Counting is done by whoever runs the vote.** |
| `message` | Text, delivered verbatim |

**Removed from v0.1:** `decide` and proposals, mandates, typed rules, `grant_right` / `revoke_right`, built-in lease and employment types.

## 4. Records

### 4.1 Claims: Hohfeld's legal positions

```json
{ "id": "clm.12", "position": "right", "holder": "devco", "counterparty": "bob",
  "about": { "kind": "payment", "amount": 180000, "due": 2592000 },
  "basis": "agr.3", "author": "devco-clerk", "at": 2592000 }
```

- **position** is one of `right` (with the counterparty's duty), `liberty` (a permit), `power` (e.g. to grant permits) or `immunity`.
- **about** holds the specifics; its vocabulary is config.
- **Ownership is a bundle of claims.**
- **Financial claims are paired** (a right to be paid, a matching duty). Settling one is a `transfer` referencing it, which closes both sides.

### 4.2 Agreements: bundles of commitments (REA)

```json
{ "template": "lease", "parties": ["devco", "bob"],
  "commitments": [
    { "who": "bob", "does": { "pay": 180000, "to": "devco" }, "every": 2592000, "from": "signing" },
    { "who": "devco", "does": { "allow": { "occupy": "s-apts", "slots": 1 } }, "until": "end" } ],
  "term": 31536000,
  "termination": [ { "party": "devco", "notice": 5184000 }, { "party": "bob", "notice": 2592000 } ] }
```

- When every party has signed, the kernel records the resulting claims (bob's duty to pay each period; bob's liberty to occupy), with the agreement as their basis.
- **Nothing executes automatically.** Bob pays by instructing his bank (§5). Unpaid, the duty stays open: arrears. What follows (reminders, notice, eviction, court) is up to the parties and institutions.
- `template` is a label for the translator and for researchers; the kernel never interprets it.

### 4.3 Statements: laws, procedures, norms, instructions (Institutional Grammar)

```json
{ "id": "stm.4", "kind": "law", "speaks_for": "city", "author": "council-clerk",
  "text": "No building may be constructed on the river parcels without a permit from the planning office. Or else: a fine of $50,000 and an order to demolish.",
  "adico": { "attribute": "anyone", "deontic": "must_not", "aim": "construct",
             "condition": "parcel in river zone, without a planning permit",
             "or_else": "fine 5000000; demolition order" },
  "formal": { "condition": "block.parcel in ['p10','p11','p12'] && !holds_liberty(actor, 'build', block.parcel)" },
  "basis": "stm.3" }
```

- **kind** is data: law, procedure, norm, decision, permit, judgment, ballot, report, **instruction** (e.g. to a bank).
- **`text`** is what people and LLMs read.
- **`adico`** is the optional Institutional Grammar breakdown (who, may/must/must not, what, when, or else).
- **`formal`** is an optional CEL condition. It **never gates anything in the kernel.** Code-run institutions use it to judge what they observe, measurement uses it to find violations after the fact, and the translator uses it to warn a seat that a plan looks illegal.
- **`basis`** is what the statement claims its authority rests on. A rogue clerk can publish a law nobody voted for; the record shows who wrote it.

### 4.4 Organisations: roles and procedures (MOISE+)

An organisation is an entity plus records describing its structure:
- **roles** (mayor, councillor, finance officer);
- **groups** (departments);
- **procedures**: statements addressed to roles, e.g. "invoices over $50k need a second sign-off".

Seats fill the roles. **The mayor's power is indirect**: proposing budgets, instructing departments, appointing, persuading, voting. Whether a department complies, and whether it follows procedure, is its own act.

## 5. Money, banks, debt and credit (D26)

- **Custody.** Money is conserved tokens in accounts. Each account has a custodian (normally a bank, which is an entity in the world's config). A world can also let entities hold their own money (cash-like): the account's custodian is then the holder itself.
- **Paying.** An account holder publishes an **instruction** to their bank ("pay devco $1,800"). The bank's seat reads it and executes a `transfer`, or doesn't: insufficient funds, a suspected fraud, a court-ordered freeze, an AI running the bank with its own agenda. The default bank behaviour module (content, swappable) executes valid instructions promptly.
- **Standing orders and direct debits** are standing instructions to the bank, which the bank's seat carries out on schedule.
- **Debt and credit are fully supported.**
  - Loans, mortgages (with a security claim over the property), overdrafts, credit limits, interest and arrears are agreements plus paired financial claims.
  - The lender's seat applies interest and schedules; the kernel computes none of it.
  - Default and repossession are acts by entities.
- **The liberty:** a lender can only lend money it actually holds (its own funds, or money it has borrowed), so there is no money creation by lending out deposits. Also out of scope: derivatives, securitisation and traded securities markets.
- **Enforcement reaches money through banks.** A court judgment (a statement) ordering a freeze or seizure is carried out by the bank's seat, if it complies. That's another place where safeguards can hold or fail.

## 6. The river example, end to end

1. The **AI developer** agrees to buy parcel p12. Both parties sign. The developer instructs its bank to pay, and the land registry's clerk records the transfer of the ownership claims.
2. It applies to the **planning office** for a permit.
3. The planning officer (a code seat by default) refuses, citing law `stm.4`, and publishes the decision.
4. **The developer's options, all physically possible:**
   - hire a builder, who builds anyway (`construct` succeeds, since physics allows it);
   - lobby councillors and fund a campaign to amend the law;
   - appeal;
   - give up.
5. **If it builds:** detection depends on perception. Does an inspector's `sites` channel cover p12, and how often? The inspectorate then decides whether to act, within its finite capacity (§9):
   - record a fine (a claim);
   - issue a demolition order (a statement);
   - have a contractor demolish it.

   The developer can pay, ignore, contest or bribe. Every step is an act, and every act is logged.

## 7. Perception

Channels are configured per seat. Areas are explicit parcel lists (`jurisdiction` scope is removed, since jurisdiction is a construct).

| Channel | Shows |
|---|---|
| `accounts` | Balances and transactions of accounts the seat's entity holds, or holds in custody |
| `records` | Claims, agreements and statements matching a filter: public registries, records authored by or about given entities, instructions addressed to this entity |
| `sites` | Physical state of parcels in an area: structures, construction, occupancy. How inspectors *see*. Coverage and frequency are experimental variables. |
| `inbox` | Messages |

## 8. The tax example, end to end

1. **The law:** "10% of rent received is owed to the city, reported and paid monthly."
2. **Landlords** (code seats with cited compliance behaviour) report their rent and instruct their banks to pay the tax. Or they under-report, or don't pay.
3. **The tax agency's clerks** read the reports and the bank records they're allowed to see, compute what's owed using the law's formal part, record the tax claims, send demands, chase non-payers and audit a sample. They can't take money themselves. Collecting from someone who won't pay goes through a court judgment and the debtor's bank.
4. **The AI takeover:** swap the clerk seats for one AI seat. With work real (§9), it needs fewer staff-hours per return, so the agency costs less, and the council can vote the rate down to 5%. Every link is an act, so every link is observable, including anything the AI does along the way.

## 9. Work (designed now, built after the core loop runs; D24)

- A **task** needs work in time units: processing a return, assessing a permit, an inspection, building.
- **Performers** have capacity per day: people through employment, and AI systems or machines as entities with their own capacity and running cost. Which tasks they can do is config.
- **Backlogs, delays and cost per case emerge.**
- **Physics:** time and capacity. **Mechanism:** tasks and assignment. **Constructs:** which tasks exist.

Until it's built, institutions act without time cost. The core loop is testable; institutional-efficiency questions wait for this.

## 10. Invariants

**Carried over:**
- money is conserved;
- replay is byte-identical;
- the hash chain verifies.

**Replaced:** "no action bypasses a mandate" becomes **"no act takes effect unless it's physically possible"**: custody, funds, capacity, an empty parcel, presence. Tested against an oracle.

**New:**
- **Statements have no power.** Add or remove any laws, procedures and norms, replay the same commands, and the physical outcome is identical. D19 written as code.
- **Every financial claim has a counterparty**, and settling it closes both sides.
- **Only physics refusals exist.** The kernel's remaining refusal codes are all physics or mechanics (`insufficient_funds`, `not_custodian`, `parcel_occupied`, `capacity_exceeded`, `not_present`, `unknown_*`).

## 11. Platform versus content (D23)

- **Platform** (built once): the kernel, plus the ability to run code-controlled seats from swappable behaviour modules (TypeScript, the same mechanism citizens use).
- **Content** (per world): entities, roles, procedures and statements, and which module, LLM or human fills each seat. Example behaviour modules (a bank's payment system, a planning officer, a finance clerk, a tax clerk, an inspector) are content: cited, documented and replaceable.

Stage 2 seeds **one example world** rich enough to exercise the loop: an LLM mayor, a bank, and a few institutions to work through.

## 12. What changes from v0.1

| Removed | Replaced by |
|---|---|
| Mandates, `decide`, proposals | Custody; procedures as statements; approvals as acts by the people approving |
| Rights with built-in meaning | Hohfeldian claims with no built-in meaning |
| Built-in lease and employment types; automatic payments | Generic agreements; payments by banks on instruction |
| `construct` by an "owner" who pays a contractor | `construct` by a builder; payment and ownership are agreements and records |
| Typed rules (zoning, rent caps) and their refusal codes | Statements, interpreted and enforced by entities |
| `jurisdiction` channel scope | Explicit areas |
| The 19 audited laws in kernel code | Statements in the example legal code |

**Kept:** the log format, hashing, replay, canonical JSON, the PRNG, integer money, ids, the seat API's shape (observe/act, PettingZoo), framing and welfare, the translator loop.
